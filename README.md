# Задание 1

## Уровень 1. Проектирование

Будем использовать инструмент Webpack Module Federation, так как мы работаем в рамках одного frontend фреймворка React.

Для решения поставленной задачи лучше подойтет стратегия с вертикальной нарезкой. Так как в проекте нет необходимости использовать разные технологии. Так же нет потребности полностью изолировать друг от друга разные микрофронтенды. Но есть потребность разбить микрофронтенды на разные бизнес задачи(домены)

## Уровень 2. Планирование изменений

На базе предоставленного приложения систему можно поделить на следующие микрофронтенды:
1. Host - Точка входа для всего приложения и медиатор между остальными микрофронтендами
2. Auth - Микрофронтенд отвечающий за аутентификацию пользователей
3. Places - Микрофронтенд отвечающий за работу с фотографиями достопримечательностей. Добавление, удаление, лайки
4. Profile - Микрофронтенд отвечающий за информацю о пользователе.

В микрофронтенд `Places` добавлен новый компонент `Places` и имплементирован в компонент `Main` микрофронтенда `Host`.

В микрофронтенд `Profile` добавлен новый компонент `Profile` и имплементирован в компонент `Main` микрофронтенда `Host`.

Каждый микрофронтенд в основном оперирует своими собственными данными, поэтому утилиту `api` можно разделить на 2 части (`Places`, `Profile`) и вынести методы под конкретые задачи. Исключением является `CurrentUserContext`. Информацию о пользователе нужно отображать в разных частях проекта. Поэтому общий стейт шерится между всеми фронтендами через `CurrentUserContext`

Для функционала `closeAllPopups`, можно изпользовать механизм с шиной сообщений.
